# lab-report-framework

大学理系の実験レポートを、学生本人が本文を書き、Codexが実験・分析・骨格・組版・検証を支えるローカル環境です。GitHubから取得した `lab-report-framework/` 直下をCodexの作業ディレクトリにしてください。

## 基本原則

- 本文の文章はすべてユーザーが書きます。Codexは空欄を代筆しません。
- 実験前に実習書、課題文、採点基準を全読し、計画と評価条件を確認します。
- 実験・分析後、見出し、図表、数式、コード、参考文献と `(文章N)` を配置した骨格PDFを作ります。
- ユーザーが `文章1: ...` の形で本文を送り、Codexが原文を保存して誤字脱字とTeX組版を行います。
- 意味、数値、因果、結論、断定の強さを変える修正は、ユーザー承認なしに確定しません。
- 完成後、採点基準ごとに教授視点の模擬評価を行い、弱点も報告します。

## 使い方

実習書、課題文、採点基準、配布データを渡し、次のように依頼します。

> この実験を始めたい。実習書と採点基準を全読し、G1確認票を作って。

大きな本人承認は3回です。意味変更や実験条件の重要な変更が必要な場合だけ追加相談します。

| 確認 | ユーザーが見るもの |
|---|---|
| G1 実験前確認 | 課題解釈、採点基準、表紙、AI規則、実験計画 |
| G2 証拠・骨格確認 | 実験結果、除外、出典、骨格PDF、各文章枠の執筆要件 |
| G3 完成稿・提出確認 | 本人原文の反映、最終PDF、教授視点評価、提出可否 |

G2承認後は、Codexが示す執筆メモに沿って文章を送ります。

```text
文章1:
（自分で書いた本文）

文章2:
（自分で書いた本文）
```

Codexは原文を `prose/original/P-xxx.md`、組版済み本文を `prose/typeset/P-xxx.tex` に保存します。

「文章3を差し替えて」と送れば、旧版を保管して反映できます。複数枠をまとめて送っても構いません。普段あなたが読むのは執筆案内、日本語の変更説明、確認が必要な点、PDFです。内部YAMLやTeX差分を毎回読む必要はありません。

v7.1では、再開時の次の作業表示、原文の一括受領・差し替え、監査資料の自動生成を追加しました。内容を変えない限定的な体裁調整は完成時にまとめて確認します。操作と制限は [日常の進め方](docs/DAILY_WORKFLOW.md) を参照してください。従来の完成例と様式は維持しています。

## 標準様式

v7.2では、課題ごとの既習範囲・後続課題から持ち込まない内容・指定条件・コードの役割・コメント方針をG1で確定します。骨格と完成稿で課題別に照合します。新規実験では設定が必須です。意味判断はCodexと本人が行い、Pythonは範囲の宣言・対応・確認記録を検査します。

実装に基づく全体説明は [現在のシステム仕様](docs/SYSTEM_SPEC.md)、全データ項目は [スキーマ一覧](docs/SCHEMA_REFERENCE.md) を参照してください。

- A4、1段組、本文10.5pt相当、余白25mm
- 本文明朝、見出しゴシック、ヘッダなし、ページ番号のみ
- 表紙直後から本文。タイトル、氏名、概要、キーワードを再掲しない
- 表紙項目は実験ごとに指定し、項目ブロックを中央配置
- 本文で先に参照し、図表を近傍のページ上端・下端へフロート配置
- 図キャプションは下、表とコードは上
- 軸、凡例、表見出しは英語が必要でない限り日本語
- URLは黒、枠なし、本文と同系統の書体で余白内に折り返す

詳細は [利用ガイド](docs/USER_GUIDE.md) と `rules/` を参照してください。

文章は一枠ずつ送れます。途中の下書きでは未記入枠を残し、最終候補では全枠の完成を検査します。Codexは原文との差分を示し、意味を変える修正には対象文章の本人承認を求めます。

v7では生成入力・PDF・確認記録の版を照合します。古いPDFや確認記録、再生成していない結果を検査済みとして扱いません。教授視点評価は教員配点がない場合に点数を作らず、不足と根拠を示します。v6以前の実験は [移行・検証手順](docs/RELIABILITY.md) に従って再確認してください。

## 最終成果物

`experiments/<id>/deliverables/` に次を固定します。

- `report.pdf`
- `HANDOFF.md`
- `PROFESSOR_EVALUATION.md`（本人確認用。通常は教員へ提出しない）
- `SOURCE_AUDIT.md`
- `RESULT_TRACEABILITY.md`
- `WORKLOG.md`

## ローカル診断

通常はCodexが実行します。手動確認する場合だけ次を使います。

```powershell
python scripts/doctor.py
```

GitHub Actionsはフレームワーク変更時の手動検査用で、普段のレポート作成には不要です。完成例は `examples/sort-benchmark/` にあり、架空データによる回帰検証専用です。
